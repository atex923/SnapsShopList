# SnapsShopList V0.9.0 快速模式規劃

狀態：V0.9.0 第一版已實作；實體手機相機、相簿與權限流程待下次同步時驗證

## 一、模式與首頁

### 設定頁

- 新增「顯示快速模式開關」，預設關閉。
- 關閉時，首頁不顯示快速模式開關，避免誤觸。
- 此設定屬於長期偏好，使用 `AppStorage` 保存。

### 首頁

- 設定齒輪移到左上角。
- 右上角顯示快速模式開關，但只在設定允許時出現。
- 快速模式開／關只保存於目前 App 執行期間：切到背景或鎖定手機不改變；使用者從多工畫面完全關閉 App 後，下次啟動回到關閉。
- 建議由 App 根層的 `QuickModeSession` 保存狀態，不寫入 `UserDefaults`，避免下次冷啟動仍意外開啟。
- 快速模式開啟後，首頁下半部固定顯示 App 小圖案與藍色實心圓形相機鈕；相機鈕採黑白相機圖案。
- 條碼掃描後，首頁顯示商品資訊卡；相機鈕不隱藏。
- 使用者可以繼續掃描，也可以點商品卡進入快速紀錄或後續正式編輯。

## 二、快速紀錄流程

流程：掃描或拍照 → 快速填寫 → 暫存 → 從商品卡補充資料 → 選取最多5張正式照片 → 正式儲存。

### 快速儲存畫面

畫面不顯示一般欄位標題區塊，維持緊密排列，但每個控制項仍須提供 VoiceOver 名稱：

1. 條碼區。
2. 相片區，暫存上限10張。
3. 價格，唯一建議的必要欄位；無有效價格時不可暫存成比價紀錄。
4. 數量，選填且預設空白。
5. 容量，選填。
6. 單位，選填並沿用輸入記憶。
7. 特價開關。
8. 買一送一開關。
9. 商品名稱，選填；海外模式提供 OCR。
10. 店家，選填；海外模式提供 OCR。
11. 紀錄時間，自動帶入且可在正式編輯時修正。
12. GPS 狀態；沒有定位仍可暫存。

每個文字或數字欄位提供清除按鈕；鍵盤維持右下角收合入口。

## 三、10張暫存照片與5張正式照片

- 快速模式照片最多10張，先放入本機暫存區，不立即建立正式 `ProductPhoto`，也不立即上傳雲端。
- 暫存資料需要保存照片建立時間、來源、方向與可用的原始 metadata。
- 正式儲存時顯示10張縮圖，讓使用者勾選最多5張；依拍攝時間由早到晚排列。
- 確認後才壓縮並轉成正式商品照片；未選照片在完成儲存後刪除。
- 若取消正式編輯，保留暫存資料；若刪除快速草稿，再一併清除其暫存照片。
- 必須設計暫存檔清理機制，例如刪除30天未修改的孤立暫存檔，但清理前不可刪除仍有草稿索引的照片。

## 四、資料模型與比價規則

### 建議新增欄位

- `recordStatus`：`quickDraft`、`comparison`、`complete`。
- `quantityWasEntered`：區分空白數量與使用者真的輸入1。
- `quickDraftID`：連結本機10張暫存照片，不把暫存照片直接寫進 CloudKit。
- `locationSource`：`liveGPS`、`photoMetadata`、`manual`、`none`。

為避免破壞既有資料，舊紀錄升級時使用：`recordStatus = complete`、`quantityWasEntered = true`、`locationSource = liveGPS` 或 `none`。

### 數量空白

- 仍寫入採買紀錄並出現在「歷次比較價格」。
- 仍可供價格記憶助手比較原始價格。
- 不列入海外購物數量庫，也不計入累計購買數量。
- 因數量未知，不顯示每件真實單價；只有容量與單位可確認時，才顯示明確標註為「依標示容量換算」的每100 g／ml價格。
- 最低價、最高價及平均趨勢不可把「未知數量的總價」與「已知多組總價」當成同一種單價直接排序；畫面需分成原始價格與可換算單價兩種統計。

## 五、詳細資料

- 新增「歷次比較價格」卡片，收錄 `comparison` 與 `complete` 紀錄。
- 預設顯示時間、店家、原始價格與資料完整狀態。
- 可換算時再顯示單價；數量空白時顯示「數量未填」。
- 價格記憶助手可使用此區資料，但須依相同貨幣、容量與單位分組，避免台幣／外幣或不同規格混算。
- 點擊快速暫存商品卡進入完整商品編輯，補齊其他資料並完成正式儲存。

## 六、海外模式 OCR 與相簿

- 海外模式才顯示「從相簿擷取文字」，國內模式不載入 OCR 工作流程。
- 使用系統 PhotosPicker 選圖後，以 Apple Vision 在裝置端辨識商品名稱與店家。
- 辨識結果先顯示候選文字，由使用者點選後才填入，不自動覆蓋既有內容。
- OCR 不上傳照片；若未來加入 AI 或網頁搜尋，必須另有明確確認畫面。
- 正式編輯時可嘗試讀取選取照片的定位 metadata。只有照片確實帶有位置且相簿權限允許時才填入 GPS；沒有 metadata 時維持「未取得」，不可猜測位置。

## 七、狀態流程

```text
首頁快速模式
  ├─ 掃描條碼 ─→ 顯示既有／新商品卡
  ├─ 快速相機 ─→ 建立或接續快速草稿
  └─ 點商品卡 ─→ 快速輸入
                      ├─ 暫存 ─→ 回首頁，可繼續掃描
                      └─ 正式編輯 ─→ 補資料＋選5張照片 ─→ 正式儲存
```

同一草稿的暫存按鈕必須做防重複提交；返回首頁後立即顯示最新卡片，不等待雲端同步。

## 八、跨平台與同步界線

- `quickDraft` 與10張暫存照片預設只留手機本機，不同步到 macOS／Windows。
- 轉為 `comparison` 或 `complete` 後才加入 `.snapssync` 與 CloudKit 交換資料。
- macOS 版未支援新欄位前必須保留未知 JSON 欄位；未完成的手機快速草稿不應出現在桌機。
- Python／Windows 未來需辨識 `quantityWasEntered = false`，不得把空白數量自動改成1後回寫。

## 九、建議實作順序

1. 建立快速模式設定、執行期間狀態與首頁排版。
2. 建立快速草稿資料及10張本機照片暫存區。
3. 完成快速輸入、暫存、防重複提交與首頁商品卡。
4. 完成正式編輯時的5張照片挑選及草稿清理。
5. 加入相簿 OCR 與照片 GPS metadata。
6. 修改海外購物數量庫與價格統計的未知數量規則。
7. 更新備份、同步、macOS 相容說明與 migration 測試。

## 十、驗收條件

- 完全關閉 App 後快速模式必定回到關閉；單純切背景或鎖定不改變狀態。
- 設定關閉「顯示快速模式開關」後，首頁不出現該開關。
- 快速模式相機鈕在掃描結果出現後仍保持可用。
- 可連續暫存10張照片，正式儲存不得超過5張。
- 數量空白紀錄會進入比價資料，但不進海外購物數量庫且不增加累計數量。
- 無 GPS、無商品名稱、無店家時，只要價格有效就能暫存。
- 相簿 OCR 只在海外模式啟動，辨識結果不自動覆蓋。
- 舊 V0.8.3 資料、schema 3 備份及現有5張正式照片流程可正常升級。
- 通過 iPhone 16／iPhone 17 Pro 模擬器畫面、Build、Analyze、資料 migration、備份匯入與實體手機拍照／相簿權限測試。
